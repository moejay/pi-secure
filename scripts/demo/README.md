# Rebuild the example workflow

These development-only scripts generate the existing `docs/media/preview.png`, `demo.mp4`, and `demo.vtt` URLs. They are not included in the published package.

## Run

Requires macOS system Menlo/Georgia/Arial fonts, Node.js and installed project dependencies, `pi`, `rg`, `fd`, Python 3, and `/opt/homebrew/bin/ffmpeg` (`ffprobe` for validation).

```sh
TOOLS="$(mktemp -d /tmp/pi-secure-media-tools.XXXXXX)"
python3 -m pip install --target "$TOOLS" pyte Pillow
export PYTHONPATH="$TOOLS${PYTHONPATH:+:$PYTHONPATH}"
python3 scripts/demo/capture.py
# Use the temporary directory printed by capture.py:
python3 scripts/demo/render.py /path/printed/by/capture/frames.json
/opt/homebrew/bin/ffprobe -v error \
  -show_entries stream=codec_name,width,height,pix_fmt \
  -show_entries format=duration,size -of json docs/media/demo.mp4
```

## What actually runs

The capture starts an offline Pi process on a real 112×25 PTY, in a temporary working directory with isolated HOME and agent settings, an explicit environment allowlist, and no saved session, built-in tools, automatic extensions, MCP, skills, templates, or context files. Only this driver and theme are explicitly loaded. No model is called; a synthetic CLI API-key override suppresses startup warnings and is never sent to a provider.

The driver imports the real root extension and intercepts its registered tool/command definitions. A local `/demo` command directly invokes their actual implementations with Pi's UI context. Inputs are scripted, not generated by an agent. A custom narration renderer emits plain editorial request/result labels instead of default custom-message boxes; these labels are not model reasoning or model-issued tool-call records.

The driver binds an ephemeral HTTP server to `127.0.0.1` only. Its private `/builds/latest` endpoint rejects a request without authentication with HTTP 401. The real `request_secret` component accepts `example-local-api-token` as `BUILD_TOKEN`. The real `secure_exec` injects it into the environment and runs `curl` with a Bearer header against that localhost endpoint. The fixture verifies the header and returns build 184, branch main, status passed, checks 12 / 12. The driver asserts exact output, exit 0, and one authenticated request. This is local fixture data, not a claim about any external build service.

The actual `show_secret` tool then opens its real component (non-overlay for legibility). R, Y, R, Enter confirm reveal, hide again, and close. **C remains visible but is never pressed; no clipboard callback is simulated or invoked, and no native clipboard read/write occurs.** The actual `/secret clear` handler clears the vault; another real `secure_exec` verifies the name is unavailable. A `verification.json` file in the temporary capture directory records successful assertions. The server closes in a `finally` block.

The renderer paints captured ANSI terminal cells with pyte/Pillow inside editorial window chrome. It adds a title and captions, resamples at 10 fps and holds the final state to a 24-second timeline, then encodes silent 1280×800 H.264/yuv420p at 30 fps with faststart. The same-size PNG uses a captured masked local-inspection state. VTT mirrors the burned-in captions. Raw terminal recordings, verification, and frame snapshots remain in temporary directories.

## Boundary

Only use the synthetic token above: the raw capture deliberately retains the locally revealed value. No external network, real credential, provider request, or native clipboard operation is needed. This is transcript hygiene, not a sandbox or protection against a malicious/prompt-injected model. Commands retain ordinary OS permissions and can exfiltrate or transform secrets; exact-value output redaction does not cover every encoding. Clearing the vault does not erase recordings or files.
