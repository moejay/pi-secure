01 / INPUT

Ask without the paste.

request_secret opens a masked terminal dialog. The agent receives only a name and availability—not the value. Cancel any time before submitting.

02 / CAPTURE

Stdout stays private.

capture_secret stores a command’s stdout directly in extension memory. Neither stdout nor stderr is returned to the agent, even on failure. Commands and paths are still logged.

03 / LOCAL ACCESS

Reveal on your terms.

show_secret opens a masked local dialog for up to 30 seconds. Press R to reveal/hide or C to copy without revealing. Reveal and copy require explicit confirmation; only shown/copied status returns to the agent.

Clipboard managers, history, and sync may retain copied values. The clipboard is not automatically cleared.

04 / EXECUTION

Use it. Redact the echo.

secure_exec injects named secrets into child-process environment variables. Output is buffered; exact known values are redacted from stdout and stderr before returning.

Not pattern detection: encoded or transformed values can escape redaction. Other tools’ output is not covered.

Cleaner transcripts.

Read the full security boundary ↗

Not a defense against a compromised model.

A malicious model, or one following a prompt injection, can still obtain or leak secrets through its tools. It could write a secret to a file and read it back, send it elsewhere, or transform it to bypass exact-value redaction. pi-secure does not prevent prompt injection or enforce secret isolation. Reveal/copy confirmations do not protect other tool paths. Use external sandboxing and network restrictions where needed, plus short-lived, least-privilege credentials.

Trust the task and the destination.

Commands can access files, send data, or save credentials. There are no destination or file-access restrictions. Never put literal values in chat or tool arguments; names, reasons, commands, and availability are logged normally.

Local doesn’t mean unobservable.

Terminal input recording, scrollback, screen capture, host extensions, process inspection, debug logs, crash dumps, and the operating system are outside this protection. Revealing a value is not recording-proof.

Forget is not erase. Or revoke.

Values live in extension memory and are forgotten on clear, reload, session start, or shutdown. JavaScript memory is not guaranteed to be zeroized. Clearing does not revoke credentials or erase subprocess copies. Prefer short-lived, least-privilege tokens.
